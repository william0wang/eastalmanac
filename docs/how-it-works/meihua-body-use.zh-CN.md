# 梅花易数体用分析：同一卦象的五行断法

_最后校验：2026-10_

## 摘要
梅花易数是 EastAlmanac 的第二种易经断法——它最深的设计决策在于与铜钱卦**共享**的东西：同样的笔画、同样的起卦时刻、同样的三个数、同样的卦。差异只在断法框架。它不引动爻的古经文，而是读**两个三爻卦之间的五行生克**——古典的体用总诀。引擎把卦分成体卦与用卦、求出互卦，并把每一层（用、互、变）对体作五档判定。全程纯函数；同一卦的体用面板是确定的。

---

## 1. 一次起卦，两种断法

起卦页在同一画布后挂两种方法。推导演链（笔画 → 三个数 → 六爻 → 本卦/动爻/变卦）**只算一次、双方共享**。回传 payload 标明你拿到的是哪种：

| `input.method` | 断法框架 |
|---|---|
| `"coin"` | 动爻古经文（朱熹规则） |
| `"meihua"` | 五行体用面板（`result.tiYong`） |

## 2. 体用划分——钉死的规则

铜钱卦可能**多爻齐动**——古典的年月日时起卦从不会这样。因此引擎钉死唯一确定的划分：

1. **用 = 含动爻的三爻卦**；安静的那个是体。
2. **两卦皆动** → 动爻**多**者为用；**平局取上卦**（`useIsUpper = changingUpper >= changingLower`）。
3. **全静之卦** → 不分体用：`ti`/`yong` 为 `null`，直接读卦辞——与铜钱卦读法一致。

**各条规则的出处**：规则 1 是古典原文——「凡上下二卦无动爻者为体，有动爻者为用」（《梅花易数》）。但古典的年月日时起卦**有且只有一个动爻**，规则 2–3 因此没有任何古典先例可循；流传各派处理铜钱卦多动爻时，取最初/最下动爻（或以世爻定体用——该派自注「非古法」）。本引擎的「动多者为用、平局取上卦」是公开发布的实现约定——确定、可复现，且在古典实际覆盖的单动爻情形与古典完全一致。

每个三爻卦的身份（名 + 五行）来自标准八卦表：乾金 坤土 震木 巽木 坎水 离火 艮土 兑金。

## 3. 互卦

互卦重读事情的**中段**——第 2–4 爻（1 起算）为下互、第 3–5 爻为上互，本身是一完整卦，以文王卦号命名。面板报出卦名与两互的卦名五行。

## 4. 五档判定（体用总诀）

每一层——用卦、两个互卦、变卦的两个三爻卦——都按其五行对**体五行**的作用定档：

| 关系 | 方向 | 判定 | 一句话含义 |
|---|---|---|---|
| 生体 | 层生体 | `auspicious` 大吉 | 事情来滋养你 |
| 体克 | 体克层 | `auspicious` 小吉 | 你掌握事情 |
| 比和 | 同五行 | `harmony` 吉 | 顺畅、低摩擦 |
| 体生 | 体生层 | `draining` 耗泄 | 你为事耗神费财 |
| 克体 | 层克体 | `controlled` 受制 | 事情压制你 |

`ladder` 数组按**阅读顺序**排列各层——先用卦（现在）、再上互下互（过程）、最后变卦上下卦（走向），每条形如 `层·名:关系`。

## 5. 金样演算——还是那组 `[7, 23, 41]`

取三数起卦文档里的同一卦：数字 `[7, 23, 41]` → **家人**（下离火、上巽木），第 1–4 爻动，第 5–6 爻静。

**体用划分**——下卦含 3 个动爻、上卦 1 个，动多者为用 → **用 = 下卦离火，体 = 上卦巽木**。

**互卦**——第 2–4 爻 = 阴阳阴 = 坎（水），第 3–5 爻 = 阳阴阳 = 离（火）→ 互卦未济。

**变卦**——第 1–4 爻翻转 → 下坎上乾 → 讼（文王 6）。

**体用阶梯**（体五行 = 木）：

| 层 | 五行 | 对木的作用 | 关系 |
|---|---|---|---|
| 用卦 离 | 火 | 木生火 | 体生（耗泄） |
| 互卦 上互·离 | 火 | 木生火 | 体生（耗泄） |
| 互卦 下互·坎 | 水 | 水生木 | 生体（大吉） |
| 变卦 乾 | 金 | 金克木 | 克体（受制） |
| 变卦 坎 | 水 | 水生木 | 生体（大吉） |

按阶段读：事情本身耗你（用泄体）、中段先费劲后得助（互先泄后滋）、走向既有压力又有滋养（变卦先克后生）。落到人话：**这件事要真投入，中途有人帮一把，结果耗损能收回一部分——不是轻松的赢面，也远不是输局。**

## 6. 边界情形

- **全静卦**：`ti`/`yong` 为空、`targets` 为空——按铜钱卦读卦辞。
- **六爻全动**：引擎刻意把变卦编码报为本卦（之卦彖传读法）——面板以爻动为准，绝不以 `zhiGuaCode ≠ benGuaCode` 判断。
- **动爻数打平**：上卦为用。
